## 1. ライブ／事前収録の切り分け

**判断基準は「ローカルLLM（gemma4:26b）を回すかどうか」だけ。** これ以外はすべてライブで動く。

| 区間 | 実行主体 | 実測所要 | ライブ可否 |
|---|---|---|---|
| 通達Diff → 更新案生成 | クラウド（ORCA） | 約47秒（実測・N-11以降） | ⚠️ **ライブ可だが長い** → 収録推奨 |
| 承認・却下・編集、原文トレース | ローカル（LLM不使用） | 即時 | ✅ ライブ |
| FAX様式PDFプレビュー | ローカル（WeasyPrint） | 即時 | ✅ ライブ |
| **Privacy Gate の「停止」実演** | **ローカル（LLM不使用）** | **即時** | ✅ **ライブ** ←後述 |
| Privacy Gate の「通過」＋日報/SOAP構造化 | ローカル（gemma4:26b） | コールド31.4秒／ウォーム2.5〜5.2秒（実測・2026-08-12） | 🎬 **収録** |
| 月報の集計 | ローカル（LLM不使用） | 即時 | ✅ ライブ |
| オフライン完走（Wi-Fi断→ローカル） | ローカル（gemma4:26b） | 数分 | 🎬 **収録** |

### なぜ Privacy Gate の「停止」がライブで動くのか

保険証番号・診察券番号・APIキー・JWT・URL内認証情報を検出すると、Gate は
**ローカルLLMを呼ぶ前に `blocked` を確定させる**（`privacy/gate.py`——`status is not BLOCKED` の
条件でLLM補完検出をスキップする）。つまり**モデルのロードも推論も発生しない＝即座に画面が出る**。

「安全側に倒す判断が、一番速く出る」というのは、そのまま設計思想の説明になる。

### #6 v2 — Before/After の落ち（実装済み機能に合わせた版）

> **旧ドラフトからの変更点**: 「審査員に録音ボタンを押させて、その場で構造化する」を**やめる**。
> 理由は2つ。(a) 現地では gemma4:26b をライブで回さない方針になった。(b) 機材操作を審査員へ
> 委ねるのは、10秒枠のブースではリスクが高い（旧ドラフトの「未確定・要ユーザー判断」で
> 自分でも挙げていた懸念）。
>
> **代わりに「審査員が押すのはボタン1個だけ」にする。** 押した結果は**事前に用意された同一の
> 発話データ**を使うので、失敗しない。

```
台詞: 「訪問のあと、車の中や事務所で、こう記録します」
   → 🎬 収録動画（8秒）: タブレットで /nippou を開き、録音 → 停止 →
      🔒 Privacy Gate の通過表示（「直接識別子を仮名化しました」）→ 日報とSOAPが同時に出る
      ※ 画面下部に「事前収録」のテロップを常時出す

台詞: 「この記録を、改定の前と後のチェックリストで並べます」
   → ✅ ライブ（2秒）: Before/After比較画面（/runs/{run_id}/before-after）で
      審査員に「比較する」ボタンを1回だけ押してもらう
      → 変更後にだけ「目標に対する評価」が現れる ← 落ち
      → 画面に「入力音声は同一。差はチェックリストのみ」を明記（批評Y-3）
```

**この構成の利点**: 落ち（G6）はライブで出る。録画は「録音して構造化される」という
**説明しづらい部分だけ**に限定されるので、「全部動画じゃないか」と言われない。

## 3. 深掘りモジュール（質問が来たら出す・各30秒）

75秒のコアには入れない。**審査員が足を止めて質問してきたときだけ**開く。

### モジュールS — セキュリティ（⑦向け・**全区間ライブ**）

```
「この記録、外に出ていないんですか？」と聞かれたら:

1. (10秒) /nippou で、保険証番号を含む発話をわざと入れて送信
   → 即座に「セキュリティ検査で停止しました」
   → 「今のは通信もモデル呼び出しも発生していません。ルールだけで止まっています」

2. (10秒) 「修正して再検査」で保険証番号を消して再送信
   → 通過して日報が出る（※ここは収録に差し替え可）

3. (10秒) /privacy/audits を開く
   → 「何を何件検出したか」だけが残り、発話原文も対応表も入っていないことを見せる
   → 「記録に残せないものは、記録に残さない設計にしています」
```

**言ってはいけないこと**（privacy.md の方針）:
- ❌「匿名化済みです」「これはもう個人情報ではありません」「完全に安全です」
- ⭕「**直接識別子を仮名化しています**。病状や服薬は残るので、取り扱いは従来どおり厳重です」

この言い方自体が審査⑦の加点になる。**限界を自分から言える**ことが技術的な誠実さの証拠になる。

### モジュールM — 月報（②向け・**全区間ライブ**）

```
「これ、記録して終わりですか？」と聞かれたら:

1. (10秒) /monthly で利用者コードと月を選ぶ → 訪問回数・訪問日数・処置別回数・
   チェックリスト項目の記入率・バイタルの推移が即座に出る
2. (10秒) 「LLMは1回も呼んでいません。全部決定論的な集計です」
   → 「加算の根拠になり得る数字が、実行のたびに揺れては困るからです」
3. (10秒) 「集計の単位は実名ではなく、利用者コードから導出した仮名です。
   このDBだけを盗っても誰の記録かは分かりません」
```

## 5. 未確定・要ユーザー判断

1. **#4「更新案の承認画面」をライブにするか収録にするか。** 保存済みのrunを開くだけならライブで
   一瞬だが、「その場で生成した」ように見せたいなら収録が要る。**誠実さを取るならライブ＋
   「これは事前に流した結果です」と一言**、を推奨。
2. **モジュールSの手順2（再検査して通過）をライブにするか。** gemma4:26b が要るのでウォーム状態を
   維持できるかによる。維持できないなら収録に差し替え。
3. **合計時間。** コア75秒は維持したが、モジュールS/Mを足すと最長135秒。ブースの回遊速度に
   対して長すぎないか。
4. **電源。** レンタルの方向とのことだが、確保できなかった場合は #4・#5・モジュールS/M も
   すべて収録に落ちる（＝ほぼ全編動画）。その場合の代替台本は別途必要。
